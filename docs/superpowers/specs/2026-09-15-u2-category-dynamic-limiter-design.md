# U2 分类动态单种限速

## 目标

新增独立 `u2-limiter` 服务，管理现有九个 qBittorrent 节点中分类严格为
`U2` 的种子。服务对每个种子设置真实的 qB 单种上传/下载限速，使 tracker
announce 区间的上传平均速率保守地低于 50 MiB/s。

## 明确不做

- 不执行放魔法，不调用 U2 的 promotion 接口，也不需要 U2 Cookie。
- 不修改 Java `u2magic` 容器、其 `runtime/data` 或现有上传选择逻辑。
- 不修改 qB 全局限速，不修改非 `U2` 分类的种子。
- 不启用 `tc`、SSH 或任何网卡级限速。

## 服务和配置

新增一个单独构建的 Python 服务及持久化卷。配置文件只包含九个 qB WebUI
节点和限速参数，凭据不写进 Git。运行时从挂载的私有配置读取。

每轮轮询：

1. 查询每个 qB 的 `U2` 分类种子及 tracker 状态。
2. 忽略 tracker 不属于配置允许 U2 tracker 主机名集合的种子。
3. 持久化每个 `节点 + torrent hash` 的上传基线、观测时间、announce 状态和
   当前由本服务施加的限速。
4. 根据本 announce 区间已上传量和距离下次 announce 的时间，计算安全的单种
   上传上限；只改变本服务管理的种子。

首次观测、状态丢失或 tracker 信息不足时，使用 45 MiB/s 的保守单种上限。
得到稳定 announce 观测后再动态调整；announce 完成且风险消除时解除本服务
施加的限速。限速值统一按 qB API 的字节/秒传递，配置使用 MiB/s。

## 安全与故障策略

- qB 请求失败：记录节点错误，不向其他节点扩散操作；保留已设置的限速。
- tracker 信息缺失：保持 45 MiB/s 的保守上限，不因不确定性放开。
- 服务停止：不批量解除限速，避免停机期间新出现的超速；恢复后从持久化状态
  继续。提供显式 `--release-managed-limits` 管理命令用于人工退出。
- 只对服务自己标记/持久化为已管理的种子解除限速，避免覆盖用户的手动限速。
- 所有日志禁止输出 qB 密码、Cookie、passkey、完整 tracker query。

## 验证

测试覆盖：

1. 非 `U2` 分类绝不调用 qB 限速 API。
2. 首次观测和 tracker 数据缺失时施加 45 MiB/s。
3. announce 周期内累计上传接近阈值时降低单种上限。
4. announce 后风险解除时只解除服务自身设置的限速。
5. 一个节点失败不影响其他节点。
6. 持久化状态在重启后恢复。

部署前先以只读诊断模式列出九个节点实际的 U2 tracker 主机名和匹配的种子数；
只有确认结果后才启用写入 qB 限速的运行模式。
