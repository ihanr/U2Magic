# U2 分类动态单种限速

## 目标

新增独立 `u2-limiter` 服务，管理现有九个 qBittorrent 节点中分类严格为
`U2` 的种子。服务对每个种子设置真实的 qB 单种上传/下载限速，使 tracker
announce 区间的上传平均速率保守地低于 50 MiB/s。

## 前提与数据来源

qBittorrent 5.1.4 的 `/api/v2/torrents/trackers` 响应不提供可用的
`next_announce`。因此，仅靠 qB API 无法计算 announce 区间，原先的“qB-only
动态模式”不成立。

动态模式改为使用运行时已有的 `site.cookie` 与 `site.uid` 对 U2 Web 页面发起
只读请求。Cookie 仅来自服务器私有配置，绝不提交到 Git、打印到日志或返回到
Web 页面。U2 Web 基地址也从私有运行配置提供，不能在代码里硬编码旧域名。

## 明确不做

- 不执行放魔法，不调用 U2 的 promotion 接口，不请求任何会改变站点状态的 URL。
- 不使用或保存 passkey；站点访问仅限带 Cookie 的 GET 请求。
- 不修改 Java `u2magic` 容器、其 `runtime/data` 或现有上传选择逻辑。
- 不修改 qB 全局限速，不修改非 `U2` 分类的种子。
- 不启用 `tc`、SSH 或任何网卡级限速。

## 服务和配置

新增一个单独构建的 Python 服务及持久化卷。配置文件包含九个 qB WebUI 节点、
限速参数、U2 Web 基地址、站点 UID 与 Cookie；凭据不写进 Git。运行时从挂载的
私有配置读取，服务器上的文件权限为 `0600`。

每轮轮询：

1. 查询每个 qB 的 `U2` 分类种子及 tracker 状态。
2. 忽略 tracker 不属于配置允许 U2 tracker 主机名集合的种子。
3. 以种子 info-hash 查询 U2 的只读搜索页面，缓存 `hash -> U2 torrent ID` 的
   映射；找不到或结果不唯一时不猜测。
4. 读取对应的只读 peer-list/详情页面，提取计算当前 announce 窗口所需的字段。
   HTML 结构或认证异常都视为观测失败。
5. 持久化每个 `节点 + torrent hash` 的上传基线、观测时间、U2 torrent ID、
   announce 观测和当前由本服务施加的限速。
6. 根据该 announce 区间已上传量和剩余时间，计算安全的单种上传上限；只改变
   本服务管理的种子。

首次观测、状态丢失、U2 页面无法解析或 tracker 信息不足时，使用 45 MiB/s 的
保守单种上限。得到稳定 announce 观测后，限速器以该周期的上传预算除以剩余时间
计算上限：前段可以高于 50 MiB/s，后段自动收紧，以使整个 announce 区间的平均值
保守地低于 50 MiB/s。计算必须保留配置化安全余量；若剩余预算已耗尽则设为极低的
保护值而不是解除限速。announce 完成且新周期基线已确认时，重新计算或解除本服务
施加的限速。限速值统一按 qB API 的字节/秒传递，配置使用 MiB/s。

## 安全与故障策略

- qB 请求失败：记录节点错误，不向其他节点扩散操作；保留已设置的限速。
- U2 请求失败、Cookie 失效、重定向到登录页或解析失败：不重试写入站点，保持
  45 MiB/s 的保守上限，不因不确定性放开。
- 站点请求允许的路径实行白名单，只能访问种子搜索、详情和 peer-list 的 HTTPS
  GET；拒绝 promotion、上传、删除及其它非白名单路径。
- 服务停止：不批量解除限速，避免停机期间新出现的超速；恢复后从持久化状态
  继续。提供显式 `--release-managed-limits` 管理命令用于人工退出。
- 只对服务自己标记/持久化为已管理的种子解除限速，避免覆盖用户的手动限速。
- 所有日志禁止输出 qB 密码、Cookie、passkey、完整 tracker query。

## 验证

测试覆盖：

1. 非 `U2` 分类绝不调用 qB 限速 API。
2. 首次观测和 tracker 数据缺失时施加 45 MiB/s。
3. U2 hash 映射不唯一或页面异常时绝不选错种子，并保持 45 MiB/s。
4. 站点请求只能发出白名单 HTTPS GET，且日志不含 Cookie/UID/完整 query。
5. announce 周期前段可计算出高于 50 MiB/s 的限速；累计上传接近预算时自动降低，
   且整个周期的预算公式保留安全余量。
6. announce 后风险解除时只解除服务自身设置的限速。
7. 一个节点或站点观测失败不影响其它节点。
8. 持久化状态在重启后恢复。

部署前先以只读诊断模式列出九个节点实际的 U2 tracker 主机名、hash 映射结果和
页面解析状态；只有确认结果后才启用写入 qB 限速的运行模式。
